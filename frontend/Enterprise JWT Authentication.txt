Enterprise JWT Authentication using RS256 (Spring Boot 3 + Spring Security 6 + Java 21)
Objective

Design and implement a centralized JWT Authentication Service as a separate Spring Boot application.

The authentication service should:

Generate RSA Public/Private Key Pair.
Sign JWT using RS256.
Expose Login API.
Generate JWT valid for 60 minutes.
Expose Public Key/JWKS endpoint (optional but recommended).
Never expose the private key.

Spring Batch applications should:

Never generate JWT.
Never have access to the private key.
Only validate JWT signature and expiry.
Reject expired or tampered JWTs.

Best Practices
Use RS256, not HS256, for enterprise systems.
Store the private key only in Azure Key Vault (or another secure secrets manager).
Share only the public key with validating applications.
Use one RSA key pair per environment (Dev, QA, UAT, Prod).
Set JWT validity to 60 minutes.
Validate signature, issuer, expiration, and optionally audience.
Use HTTPS for all communication between the authentication service and client applications.
Consider exposing a JWKS endpoint if multiple services need to validate JWTs or if automated key rotation is required.

This design is scalable, secure, and aligns with common enterprise patterns for Spring Boot microservices and Spring Batch applications.
